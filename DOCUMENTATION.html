JIRA TO YOUR BRANCH — BEFORE THE PR

Semantic Scout

Semantic Scout reads your Jira ticket and your git branch, then scores how much of the ticket is really done and what is still missing. You fix the gaps, then open the pull request. It does not prove KPI numbers in SQL — use KPI Forge and Fabric Validator for that.

Cursor MCPAny AN or PIC ticketDoes not run lakehouse SQL

Goal

Give the team an on-demand check that ticket work is on the branch before anyone opens a pull request.

Description

Semantic Scout is the delivery-truth layer for BI tickets. It lines up Jira acceptance criteria with the files you changed — dashboards, paginated reports, semantic model — and flags scope and review risks early.

Success looks like

Any ticket can be checked when needed. Each criterion shows done or still missing. Reviewers see fewer bounce-backs. You know when it is reasonable to open the PR.

What we can achieve

Same pre-PR habit for everyone instead of ad hoc checklists. Faster new-ticket intake. Less scope creep on branches.

What we can use it for

Pre-PR on every change. After DAX, RDL, or filter edits. New ticket kickoff. Self-service check before you ask for review.

What you will see

After you run it on a ticket, this is what each part means.

On the screenIn simple words
Jira scoreHow much of the ticket is reflected in your changed files.
Branch scoreHow clean the branch is for review (right files, no stray folders).
MissingsWhat Jira asked for that is not in your branch yet.
SuggestionsTypical follow-ups: documentation, dashboard vs paginated parity, things reviewers often ask for.
READYScout’s summary call. If it says no, fix missings and run again before the PR.

Who this is for

Insights / Glofox analysts on AN or PIC tickets — dashboards, paginated reports, semantic models.

How it works

flowchart TD A["Semantic Scout for AN-XXXX"] --> B["Read Jira + comments"] B --> C["Read branch changes"] C --> D["Score ticket vs branch"] D --> E["List missings"] E --> F["You fix, then open PR"]

Setup — once

  1. Open Cursor.
  2. Type Setup Semantic Scout (install deps if Cursor asks).
  3. Connect Jira and GitHub once if prompted.
  4. Run Semantic Scout for AN-XXXX on a real ticket to confirm you see the card.
You are done when you see the review card with scores and missings for your ticket.

Daily use

Before every PR: Semantic Scout for AN-XXXX (or PIC-XXXX) on your feature branch. Fix what is missing. Run again if needed. Then open the PR.

Example

Ticket: AN-XXXX — New Members paginated update Jira score: 90/100 Branch score: 85/100 READY: YES Missing: Documentation page not updated Suggestion: Align dashboard and paginated date defaults

If this happens

If you seeDo this
READY: NOFix the missings listed. Run Scout again. Do not open the PR yet.
Low Jira scoreCompare each missing line to Jira AC. Update the right report or model file.
